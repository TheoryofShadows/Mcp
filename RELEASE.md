# Releasing the MCPX npm packages

Three packages publish from this repo. Each is self-contained (vendored shared code
is regenerated by `prepack`; see `scripts/sync-shared.js`).

| Dir | Package | What it is |
|-----|---------|-----------|
| `cli/` | `mcpx` | The `npx mcpx install` CLI |
| `mcpx-mcp/` | `@mcpx/mcp` | MCP server for agents to discover/install other servers |
| `railway-mcp/` | `@mcpx/railway` | Reference MCP server for Railway |

## Pre-flight (all green as of this writing)

```bash
npm test && npm run lint && npm run build       # 209 tests, lint, build
node cli/index.js help                           # CLI loads
MCPX_API=https://www.mcpx.digital node cli/index.js list   # works against prod
node -e "import('./railway-mcp/lib.js').then(m=>console.log(m.enabledTools({}).map(t=>t.name)))"  # read-only by default
( cd cli && npm pack --dry-run )                 # tarball contents
( cd mcpx-mcp && npm pack --dry-run )
( cd railway-mcp && npm pack --dry-run )
```

## Publish

```bash
cd cli         && npm publish                      # mcpx (unscoped)
cd mcpx-mcp    && npm publish --access public       # @mcpx/* scoped → must be public
cd railway-mcp && npm publish --access public
```

`prepack` regenerates `cli/installConfig.js`, `mcpx-mcp/cliShared.js`, and
`mcpx-mcp/installConfig.js` automatically. Bump `version` in each `package.json`
before re-publishing.

## `@mcpx/railway` — validate before publishing

The Railway GraphQL operations in `railway-mcp/index.js` follow the public API but
have **not** been run against a live token. Before publishing, with a scoped
`RAILWAY_API_TOKEN`:

1. `list_projects` → confirm `projects.edges[].node { id name }`.
2. `list_services` → confirm `project(id).services.edges[].node`.
3. `list_deployments` → confirm the `deployments(input:{serviceId,environmentId})` shape.
4. `get_deployment_logs` → confirm `deploymentLogs(deploymentId,limit)`.
5. `get_variables` → confirm the `variables(...)` query (we redact values regardless).
6. Write tools (`MCPX_RAILWAY_ALLOW_WRITE=1`): `serviceInstanceRedeploy`,
   `variableUpsert`, `deploymentRollback` mutation names/inputs.

Adjust field names to the current schema (https://docs.railway.com/reference/public-api)
where they differ, re-run, then publish.

## After publish

- `npx mcpx install <slug>` and `npx -y @mcpx/railway` / `@mcpx/mcp` become live.
- List `@mcpx/railway` on MCPX with `install_command: "npx -y @mcpx/railway"`,
  tags `infra,deploy,credentials`, then verify repo ownership (Dashboard → Verify)
  to earn full provenance points.
